## Quality & Compliance Requirements

### Code Quality Standards

- Feature code MUST pass ESLint/linting with zero warnings
- All public functions MUST have JSDoc comments
- No code duplication; common patterns extracted to utilities
- Maximum cyclomatic complexity of 10 per function
- Variable names MUST be descriptive (no single-letter vars except loop indices)

### Testing Standards

- Unit tests required for all critical paths; target ≥80% coverage
- Integration tests required for feature-level workflows
- Edge cases and error conditions explicitly tested
- All tests MUST pass before merge; no skipped tests without justification

### User Experience Consistency

- Feature follows documented design system/style guide
- Consistent button labels, icons, colors across screens
- Accessibility tested against WCAG 2.1 AA minimum
- Clear loading states, error messages, success feedback

### Performance & Observability

- API response time targets: <500ms p95 (ideal <200ms)
- Page load time: <3s (ideal <1.5s) for critical paths
- Structured logging (JSON format) with context (user ID, request ID, operation)
- Performance metrics exposed; alerts configured for anomalies

### Security & Compliance

- Security review required for auth, payment, data-handling features
- Input validation enforced; no injection vulnerabilities (SQL, XSS)
- Sensitive data (PII, tokens, credentials) never logged or exposed in errors
- Audit logs maintained for sensitive operations
- OWASP Top 10 mitigations verified
